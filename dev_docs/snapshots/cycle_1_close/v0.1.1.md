# Structured Knowledge Units — v0.1.1

Structured Knowledge Units (SKUs) reconstructed from the v0.1.1 interaction log in `logs.md` (2026-08-17 → 2026-08-18). Each SKU records one design decision from the development cycle and the insight it produced.

Each SKU follows the structure defined in `guide.md`:

- **Context** — the design situation or problem addressed.
- **Design Decision** — the specific implementation or modification applied.
- **Observation** — the outcome or behaviour observed during evaluation.
- **Insight** — the interpretation explaining why the outcome occurred.

## 2026-08-17 — Codebase audit and high-severity fixes

### SKU 001 — 2026-08-17 20:26 UTC
- **Context:** The codebase needed a bug audit, and the user explicitly required it be read-only.
- **Design Decision:** Read all 45 Python source files plus the docs and the training notebook; verified suspected bugs with targeted checks; wrote `audit.md` with findings H1–H6 (high), M1–M8 (medium), L1–L8 (low). Made no code changes.
- **Observation:** A read-only audit was delivered; the BERTopic parameter plumbing was flagged as the core risk.
- **Insight:** A read-only audit (no edits) preserves a clean baseline while delivering prioritized, verifiable findings before any change is made.

### SKU 002 — 2026-08-17 20:37 UTC
- **Context:** The `.claude` folder appeared tracked, and the user asked to exclude it.
- **Design Decision:** Investigated why `.claude` was tracked and identified the root cause — the repo had no tracked `.gitignore`.
- **Observation:** The `.claude` folder was only "tracked" because the project's `.gitignore` was never committed.
- **Insight:** "Tracked" folders are often just un-ignored files — finding the root cause (no committed ignore file) comes before writing an ignore rule.

### SKU 003 — 2026-08-17 21:09 UTC
- **Context:** H1 audit finding: the parameter form rebuilt itself on every keystroke, destroying the edit mid-typing.
- **Design Decision:** `AlgorithmSettingsPanel._render()` now rebuilds the parameter form only on structural changes instead of on every keystroke; committed as `10b822e`.
- **Observation:** H1 (form destroying itself mid-edit) is fixed and pushed.
- **Insight:** Distinguishing structural changes from value changes prevents a rebuild loop where the form under the cursor is recreated by the keystroke it receives.

### SKU 004 — 2026-08-17 21:21 UTC
- **Context:** The user confirmed adding `.gitignore` to the branch.
- **Design Decision:** Created the project `.gitignore` with a `.claude/` exclusion and restored compiled artifacts from tracking; committed as `baa3443`.
- **Observation:** Claude Code worktree/plan files and compiled artifacts stay out of git.
- **Insight:** A committed `.gitignore` is only half the fix — already-tracked artifacts must be untracked explicitly, or they remain in the index.

### SKU 005 — 2026-08-17 21:24 UTC
- **Context:** The user reported having no changed files in their working copy — the branch claim was stale.
- **Design Decision:** Verified `main` had moved on; rebased `worktree-code-audit` onto current `main`, dropping the redundant `.gitignore` commit, and force-pushed with `--force-with-lease`.
- **Observation:** The branch history was reconciled with `main`; the stale claim was corrected against the live repo state.
- **Insight:** Rebasing drops a redundant commit instead of duplicating it, and `--force-with-lease` makes a force-push safe by failing if the remote moved unexpectedly.

### SKU 006 — 2026-08-17 21:59 UTC
- **Context:** The user verified the H1 fix worked and asked to fix the rest of the top-5 findings.
- **Design Decision:** Implemented H2–H6 — wizard default-parameter sync, wiring the five documented BERTopic hyperparameters into `train()`, showing the parameter UI before the first run, exception-safe event polling, and default parameter initialization; committed as `a02d9f5`.
- **Observation:** All six high-severity findings are fixed and pushed.
- **Insight:** Delivering the whole high-severity class in one commit keeps the branch's fix history readable and gives one testable unit.

## 2026-08-18 — Medium/low-severity fixes, v0.1.0 release, v0.2.0 setup

### SKU 007 — 2026-08-18 10:33 UTC
- **Context:** The medium-severity findings remained to be implemented.
- **Design Decision:** Implemented M1–M8 — thread-safe UI dispatch (`AppState.call_on_main`), training re-entrancy guard, matplotlib figure cleanup, summary-panel rebuild guard + row cap, real export panel and offline Plotly visualizer, DataLoader CSV/encoding edge cases, debug-print removal, HDBSCAN `min_cluster_size`; committed as `fdd421b`.
- **Observation:** All eight medium-severity fixes were implemented, verified with headless tests, and pushed.
- **Insight:** Thread-safe UI dispatch is the linchpin M-fix — several others only become safe once state changes reach the UI on the main thread.

### SKU 008 — 2026-08-18 11:23 UTC
- **Context:** `AttributeError: 'SummaryPanel' object has no attribute '_last_result'` at line 39 despite initialization at line 20.
- **Design Decision:** Fixed the initialization order (the attribute must be set before `_build_ui()` runs `_render()`) and used a sentinel distinct from `None` so the placeholder still renders on a fresh start; verified with a live-Tk test; committed as `0383ce1`.
- **Observation:** The M3 render guard no longer crashes at startup.
- **Insight:** A guard keyed on `None` collides with the legitimate "no result yet" state — a distinct sentinel, plus initializing before the build that reads it, resolves both the crash and the fresh-start placeholder.
